# IC Group — кабинеты клиента и администратора

Первый шаг по [ТЗ](TZ.md): экран обзора `/cabinet`. React + TypeScript + Vite, FastAPI, PostgreSQL и Alembic. Интерфейс на русском языке, для компьютера и телефона.

## Кабинет IC Group

Откройте `/admin` (локально: http://localhost:5173/admin, Docker: http://localhost:8080/admin). Он работает в том же React-приложении, независимо от клиентского экрана `/cabinet`. Для демонстрации административного кабинета backend не требуется.

В Windows из корня проекта: `powershell -ExecutionPolicy Bypass -File scripts/start-admin.ps1`. Скрипт использует установленный Node.js либо локальный `.tools/node-v22.14.0-win-x64`, подготовленный для этой рабочей копии. На другом компьютере сначала установите Node.js 22.12+ и выполните `npm ci` в `frontend`. Обычный запуск через `npm run dev` также работает.

- `/admin/requests` — анкеты клиентов с контактами, несколькими объектами, площадями, графиками, поддерживающей уборкой, расходниками, бюджетом и предварительной ценой. Поиск, фильтры города/статуса, CSV и фиксация связи с клиентом.
- `/admin/projects` — проекты, отчёты по участкам, рабочее время, отдельные условия и сметы субподрядчиков, материалы, версии и состояния документов/выплат. Фото и договоры без файлов показываются как отсутствующие.
- `/admin/complaints` — возражения клиента, рассмотрение в IC Group, отдельное подтверждение передачи исполнителям, ответ и история. Передача и ответ в демо не отправляют уведомления.

**Это временный макет кабинета, без авторизации и приёма реальных анкет.** Заявки, контакты, условия соглашений и отметки выполнения вымышлены. Изменения сохраняются только в localStorage текущего браузера. Серверной защиты административных данных и записи в PostgreSQL пока нет; реальные сведения в этот адаптер добавлять нельзя.

Структура и состав чек-листа импортированы из `02_Чек-листы_стандарт_и_пример.xlsx`, лист «Пример — Вента, ТРЦ Норд», строки 5–14. Базовые работы составляют 190 человеко-минут, доступно по примеру 360; генеральная уборка (960 человеко-минут) учитывается отдельно. Для тестовых проектов используется один пример. Повторный импорт: `python scripts/import_admin_checklist.py`.

Точка подключения приёма анкет и будущего FastAPI — `frontend/src/features/admin/service.ts`, типы — `types.ts`. Модуль загружается отдельно; главная страница и клиентский API не изменены. Для интеграции заменить локальный адаптер запросами к защищённому API и проверять роль IC Group на сервере.

Фирменные цвета, Montserrat и логотип взяты с [основного сайта IC Group](https://www.ic-group.kz/). Логотип хранится локально в `frontend/public/brand/ic-group.png`; шрифт поставляется через npm. Административные стили ограничены `.ic-admin`.

Проверки кабинета без backend, из `frontend`: `npm run build`, `npx playwright install chromium`, `npm run test:ui -- tests/admin.spec.ts`.

Проверено: production-сборка, 9 браузерных сценариев, ширины 1440/390/320 px, сохранение статусов, доступ исполнителей только после явной передачи в демо, экспорт и восстановление после ошибки локального хранилища. Повторный импорт чек-листа даёт тот же снимок. Скриншоты можно повторить командой `node scripts/capture-admin.mjs` из `frontend` при запущенном Vite.

## Реализовано

- Обзор ТОО «Медеу Девелопмент» и объекта ТРЦ «Норд».
- Архив за сентябрь 2026: выбор дня, переход по неделям, группировка работ и раскрытие списка.
- 729 плановых смен и 705 смен с обеими отметками времени. Отметки не означают приёмку уборки.
- Загрузка, ошибки с повторной попыткой, пояснения об отсутствующих документах.
- PostgreSQL, первая миграция, повторяемый демо-импорт, API и конфигурация развёртывания.

Это демонстрационный обзор одной организации. Вход, отдельные страницы объектов/договоров, загрузка файлов, обращения и АВР — следующие шаги. Публичный API `/api/v1/demo/overview` работает только при `DEMO_MODE=true` и всегда ограничен очищенным набором одного демо-клиента. Реальные клиентские данные требуют входа и проверки организации на сервере.

## Docker

Нужен запущенный Docker Desktop или Docker Engine с Compose.

```sh
docker compose up --build -d
```

- Кабинет: http://localhost:8080/cabinet
- API: http://localhost:8000/docs
- Готовность базы/API: http://localhost:8000/health/ready
- PostgreSQL: localhost:5433, база `ic`, пользователь `ic`, локальный демо-пароль `ic_local_demo`.

Миграция и демо-импорт выполняются при старте backend. Данные сохраняются в Docker volume; `docker compose down` их сохраняет. Порт базы и локальный пароль можно изменить через корневой `.env` по образцу `.env.example`.

```sh
docker compose logs -f backend
docker compose down
```

## Разработка

Нужны Python 3.12+, Node.js 22.12+ и PostgreSQL. Базу можно запустить отдельно:

```sh
docker compose up -d db
python -m venv .venv
```

Активируйте `.venv`: `.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в bash. Затем:

```sh
pip install -r backend/requirements-dev.txt
cd backend
```

Создайте `backend/.env` по образцу `backend/.env.example`:

```sh
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

Во втором терминале:

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173/cabinet. Vite пересылает `/api` на backend:8000. Для другого адреса задайте `VITE_API_URL` перед запуском или сборкой.

Экспорт не содержит ФИО, ИИН, телефоны и идентификаторы работников, условия субподрядчиков, себестоимость или маржу. Номера строк плана/факта сохранены для проверки источников. Фотографий и оформленных в системе АВР в наборе нет. Наличие исходного PDF не означает публикацию или подписание договора в кабинете.

## Проверки

Из `backend` в активированной `.venv`:

```sh
python -m pytest -q
```

Проверяются контрольные суммы, выбор даты, изоляция демо от другой организации, отключение демо и повторный импорт. Тесты используют SQLite в памяти; рабочая база — PostgreSQL.

Из `frontend`:

```sh
npm run build
npx playwright install chromium
npm run test:ui
```

Для UI-тестов backend должен работать на localhost:8000 с демо-данными. Vite запускается автоматически. Для контейнерной версии задайте `TEST_BASE_URL=http://localhost:8080`. Проверяются смена даты, раскрытие списка, мобильная навигация и восстановление после ошибки.

Проверка первого экрана: production-сборка прошла, 4 теста API и 5 браузерных сценариев прошли. Миграция и импорт проверены на отдельной локальной PostgreSQL 18; `alembic check` не обнаружил расхождений. Скриншоты проверены на ширинах 1440, 1280 и 390 px. Синтаксис Compose проверен; сборка и запуск контейнеров остаются непроверенными, поскольку установленный Docker Desktop возвращает ошибку API 500. Render и Vercel пока не развёрнуты.

## Render

Корневой `render.yaml` создаёт PostgreSQL и Docker-сервис backend через Blueprint. Укажите `FRONTEND_ORIGIN` — origin сайта Vercel без пути и завершающего `/`. `DATABASE_URL` привязывается к базе автоматически, `PORT` передаёт Render. Миграции выполняются перед запуском API.

Для демонстрации первого экрана включён `DEMO_MODE=true`. После реализации входа его можно отключить. Публикация автоматически не выполняется. Формат конфигурации: [Render Blueprint](https://render.com/docs/blueprint-spec).

## Vercel

1. Импортируйте репозиторий, задайте **Root Directory: `frontend`**, framework Vite.
2. Команда сборки: `npm run build`, каталог результата: `dist`.
3. Задайте `VITE_API_URL=https://<имя-сервиса>.onrender.com` и пересоберите сайт.
4. Добавьте origin Vercel в `FRONTEND_ORIGIN` backend. Для нескольких окружений допустим список origin через запятую.

`frontend/vercel.json` обеспечивает открытие `/cabinet` по прямой ссылке. Переменная `VITE_API_URL` содержит только публичный URL API. Документация: [Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite).

## Продолжение

Работа идёт по одному согласованному экрану:

1. Вход клиента и организация в сессии; проверки доступа к каждому файлу.
2. Карточка объекта: план, сроки услуг, чек-листы и фото до/после.
3. Договоры: публикация менеджером, версии, сроки и отдельный статус подписания.
4. Претензии в IC Group, история и управляемая передача исполнителям.
5. АВР, приёмка и отдельно подтверждённые оплаты.

Схема БД развивается миграциями Alembic. Демонстрационный импорт отделён от будущих рабочих данных. Функциональные модули UI — в `frontend/src/features`, общие компоненты — в `components`.
